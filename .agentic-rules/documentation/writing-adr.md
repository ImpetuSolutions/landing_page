# ADR writing guidelines

## Context section

- Don't justify obvious needs (e.g., "every backend needs observability").
- Focus on what needs to be observed and the decision to make.
- Keep it concise.

## Decision section

- State the decision clearly and why.
- Keep it concise, don't repeat context.

## Consequences

- **Positive**: Should be more generic/high-level.
- **Negative**: Should reflect real trade-offs.
- **Risks**: One-line description per risk (no mitigations in risks section).

## Alternatives considered

- List real alternatives that were considered.
- Explain why each was rejected.
- Keep explanations brief.
